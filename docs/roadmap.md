# 로드맵 초안

## 1단계: 개념 검증

목표: 단일 프로젝트, 소수 에이전트의 hook 상태를 수집하고 지침별 진행 상황을 화면에서 확인한다.

작업:

- hook 수신 이벤트 스키마 정의
- 신뢰도 계층 정의
- 에이전트 등록 API 작성
- hook receiver API 작성
- PostgreSQL 기반 이벤트 저장
- 최신 상태 스냅샷 조회 API 작성
- 지침별 가변 단계와 체크박스 저장
- 테스트 완료 여부 저장
- heartbeat와 lifecycle report 저장
- 간단한 대시보드 구현
- Server-Sent Events 기반 실시간 업데이트 구현
- 페이지 내부 모달 알림 구현

산출물:

- 이벤트 스키마 문서
- 신뢰도 계층 문서
- 인프라 구성 문서
- 알림 정책 문서
- 프레임워크 선정 문서
- API 초안
- 최소 대시보드
- 샘플 hook payload

## 2단계: 구독 표현과 알림

목표: 프로젝트, 에이전트, 지침 단위로 사용자가 관심 상태를 받아보고 중요한 상태를 알림으로 확인한다.

작업:

- MCP 기반 desired state와 acknowledge 검토
- 지침 버전 관리
- 구독 조건 모델링
- 브라우저 알림 구현
- 알림 권한 관리
- 실패와 테스트 완료 알림 규칙
- 알림 규칙 관리
- 이벤트 필터링 성능 개선
- 사용자별 권한 모델 추가

산출물:

- 구독 API
- 알림 규칙 문서
- 알림 설정 화면

## 3단계: 운영 안정화

목표: 장애 상황에서도 유실과 혼선을 줄이고 운영 지표를 확보한다.

작업:

- 필요 시 RabbitMQ 도입
- 이벤트 멱등 처리 강화
- 에이전트 heartbeat와 offline 판정
- 지연, 실패율, 처리량 지표 수집
- 장애 알림
- 이벤트 보존 정책 적용

산출물:

- 운영 대시보드
- 장애 대응 문서
- 보존 정책 문서

## 4단계: 다중 프로젝트 확장

목표: 여러 프로젝트와 다양한 에이전트 유형을 안정적으로 지원한다.

작업:

- 프로젝트별 권한 분리
- 에이전트 유형별 어댑터 확장
- 대량 이벤트 처리 최적화
- 프로젝트별 상태 요약 화면
- 감사 로그
- 외부 인증 연동 검토
- 필요 시 MQTT 기반 에이전트 상태 수신 검토

산출물:

- 다중 프로젝트 운영 가이드
- 권한 설계 문서
- 확장성 검증 결과
